# SC Trade — оверлей-дневник цен и маршрутов для Star Citizen

Дата: 2026-10-06. Статус: на согласовании.

## 1. Цель

Личный помощник торговца поверх игры. Игрок записывает реальные цены со своего
сервера, а приложение подсказывает, куда и что везти, засекает время рейсов и
со временем показывает, какие маршруты приносят больше всего UEC в час.

Свои замеры — главный источник. Данные UEX (uexcorp.space) — справочник и
запасной вариант там, где своих свежих данных нет.

Критерии успеха:

- Ввести цену товара на точке можно с клавиатуры за несколько секунд, не
  выходя из игры.
- Для любой точки приложение выдаёт до 5 направлений с прибылью, ROI, временем
  и UEC/час, и по каждой цифре видно, чья она и насколько свежая.
- После нескольких рейсов есть таблица собственных маршрутов, отсортированная
  по фактическому заработку в час.

## 2. Границы первой версии

Входит: ручной ввод цен, дневник, температура данных, подсказки маршрутов,
решение «продать здесь или лететь дальше», таймер рейса, статистика, оверлей.

Не входит: распознавание скриншотов, отправка цен и сделок в UEX, цепочки из
нескольких закупок подряд, добыча и переработка, синхронизация между
компьютерами, проверка совместимости размеров контейнеров.

Платформа: Windows 10/11, один пользователь, один монитор. Игра должна работать
в режиме borderless; в exclusive fullscreen окно поверх игры не показывается.

## 3. Стек

- Tauri 2. Rust — тонкая оболочка без предметной логики.
- TypeScript, Svelte 5, Vite — интерфейс и вся логика.
- SQLite через `tauri-plugin-sql`.
- HTTP к UEX через `tauri-plugin-http` (запросы идут из Rust, CORS не мешает).
- Глобальные хоткеи через `tauri-plugin-global-shortcut`.
- Логи через `tauri-plugin-log`.
- Тесты: vitest; для слоя данных — `better-sqlite3` в памяти.

Приложение не внедряется в процесс игры и не читает её память. Это обычное
окно Windows с флагом «поверх всех».

## 4. Окно

Одно окно без рамки, прозрачное, поверх всех окон, без кнопки на панели задач.
Два состояния:

| Состояние | Размер | Клики | Фокус |
|---|---|---|---|
| Полоска | одна строка, ~520×32 | проходят сквозь окно в игру | не берёт |
| Панель | ~470 px в ширину, на всю высоту экрана | принимает | берёт |

Переключение — глобальным хоткеем. `Esc` в панели сворачивает её в полоску и
возвращает фокус игре.

Полоска показывает: при активном рейсе — таймер, груз, цель и ожидаемую цену с
диапазоном, оценку UEC/час; без рейса — текущую локацию. Полоску можно
отключить в настройках, тогда в свёрнутом состоянии окно скрыто.

Иконка в трее: «Показать панель», «Выход». Она нужна, потому что полоска
некликабельна.

Хоткеи по умолчанию, все переназначаются:

- `Ctrl+Alt+T` — панель.
- `Ctrl+Alt+1` — отметка «взлетел».
- `Ctrl+Alt+2` — отметка «прилетел».

Если хоткей не удалось зарегистрировать (занят другой программой), в
настройках рядом с ним показывается ошибка.

## 5. Слои

```
src-tauri/      Rust: окно и его состояния, трей, подключение плагинов
src/core/       чистые функции, без ввода-вывода
src/data/       SQLite, клиент UEX, синхронизация, резервные копии
src/platform/   обёртки над Tauri: окно, хоткеи, HTTP, адаптер SQL
src/ui/         Svelte: полоска, панель, вкладки
tests/          vitest
```

Правила зависимостей: `core` не импортирует ничего из `data`, `platform`, `ui`.
`ui` получает данные через `data` и считает через `core`. Всё, что зависит от
текущего времени, принимает `now` параметром.

`data` работает с базой через интерфейс `Db` (`select`, `execute`). Реализаций
две: адаптер `tauri-plugin-sql` в приложении и `better-sqlite3` в тестах.

## 6. Данные UEX

База API: `https://api.uexcorp.uk/2.0/`. Нужные запросы работают без токена.
Лимит — 120 запросов в минуту.

| Запрос | Что берём | Когда |
|---|---|---|
| `star_systems` | список систем | справочник |
| `terminals?type=commodity` | торговые терминалы | справочник |
| `commodities` | товары и их коды | справочник |
| `vehicles` | корабли, SCU | справочник |
| `commodities_prices?id_terminal=…` (до 10 id) | цены с min/max/avg за неделю, месяц и всё время, остатки, спрос | цены |
| `commodities_routes?id_terminal_origin=…` | расстояния от точки до многих других одним запросом | по требованию |
| `terminals_distances` | расстояние между двумя терминалами | по требованию |

`commodities_prices_all` не используется: в нём нет min/max.

Расписание:

- **Справочник** — при первом запуске и затем раз в сутки при старте. Есть
  кнопка «Обновить справочник».
- **Цены** — при старте, если кэшу больше 60 минут, и далее каждые 60 минут.
  Терминалы запрашиваются пачками по 10 (сейчас это 14 запросов).
- **Расстояния** — лениво. При расчёте подсказок от точки сначала один запрос
  `commodities_routes` по этой точке, затем для недостающих пар из верхних 20
  кандидатов — `terminals_distances`. Расстояние считается симметричным и
  хранится бессрочно.

Поведение при сбоях:

- Первый запуск без сети: работать нельзя (нет справочника). Показывается
  ошибка и кнопка «Повторить».
- Дальше любой сбой UEX не блокирует работу: используются кэш и свои данные, в
  шапке панели виден возраст данных UEX.
- Частично загруженные цены не затирают старые: каждая пачка заменяет строки
  только своих терминалов.

## 7. База

Файл в каталоге данных приложения. При каждом запуске делается копия в
подкаталог `backups/`, хранятся последние пять.

Кэш UEX (можно стереть и скачать заново):

- `uex_star_system(id, name, code, is_available_live)`
- `uex_terminal(id, star_system_id, planet_id, orbit_id, name, nickname,
  displayname, code, star_system_name, planet_name, orbit_name, moon_name,
  space_station_name, outpost_name, city_name, has_freight_elevator,
  has_loading_dock, is_auto_load, is_available_live)`
- `uex_commodity(id, name, code, is_illegal, is_buyable, is_sellable,
  is_available_live)`
- `uex_vehicle(id, name, name_full, scu)`
- `uex_price`, ключ — пара (`terminal_id`, `commodity_id`). Для каждой стороны
  (`buy`, `sell`) хранятся: последняя цена; min, max, avg за неделю, за месяц
  и за всё время — по десять колонок на сторону. Плюс `scu_buy` (остаток на
  закупке), `scu_sell` (спрос на продаже) и `date_modified`.
- `uex_distance(terminal_a_id, terminal_b_id, distance_gm)`, где `a < b`.
- `uex_meta(key, value)` — время последних синхронизаций.

Дневник (только дописывается):

- `observation(id, ts, terminal_id, commodity_id, side, price, scu)`.
  `side = 'buy'` — цена, по которой игрок покупает у терминала; `'sell'` — по
  которой продаёт терминалу. Это совпадает с `price_buy` / `price_sell` в UEX.
  `scu` — остаток для `buy` или спрос для `sell`; может быть пустым.
- `run(id, vehicle_id, scu_capacity, started_at, ended_at, status)`,
  `status`: `active`, `done`, `lost`.
- `run_event(id, run_id, ts, type, terminal_id, commodity_id, scu, price)`,
  `type`: `buy`, `sell`, `depart`, `arrive`.
- `setting(key, value)`.

Время везде — Unix-секунды. Активный рейс может быть только один.

## 8. Логика (`core`)

### 8.1. Температура

Возраст наблюдения = `now − ts`.

| Температура | Возраст | В расчёте |
|---|---|---|
| горячая | до 60 мин | своя цена |
| тёплая | 60–180 мин | своя цена |
| остывает | 180–240 мин | своя цена, рядом показывается диапазон UEX |
| холодная | больше 240 мин | UEX; своя показывается справочно |

Пороги — в настройках. Кнопка «Сменил сервер» запоминает момент нажатия; все
наблюдения старше этого момента считаются холодными независимо от возраста.

### 8.2. Оценка цены

`estimate(terminal, commodity, side, now)` возвращает ожидаемую цену, нижнюю и
верхнюю границы, источник (`own` или `uex`), температуру и возраст.

1. Берётся последнее своё наблюдение по этой тройке. Если оно не холодное —
   ожидаемая цена и обе границы равны ему.
2. Иначе берётся строка UEX: ожидаемая = avg за неделю, границы = min и max за
   неделю. Если недельные значения нулевые — за месяц, затем за всё время,
   затем последняя цена.
3. Если нет ни того ни другого — оценки нет, терминал этим товаром на этой
   стороне не торгует.

Количество (остаток или спрос) определяется так же: своё, если не холодное,
иначе UEX. В данных UEX ноль и пустое значение означают «неизвестно» и объём не
ограничивают. В своих наблюдениях неизвестно только пустое значение, а ноль —
известный ноль (см. поправку 14.3).

### 8.3. Объём

`qty = min(свободное место, остаток на закупке, спрос на продаже, бюджет / цена закупки)`.

Свободное место = SCU корабля минус текущий груз. Неизвестные величины и
незаданный бюджет из минимума выпадают.

### 8.4. Метрики направления

- Прибыль = `qty × (цена продажи − цена закупки)`.
- ROI = `(цена продажи − цена закупки) / цена закупки`.
- Худший случай = `qty × (нижняя граница продажи − верхняя граница закупки)`.
- Время:
  1. медиана длительности своих простых рейсов между этими двумя точками в
     этом же направлении, если есть хотя бы один;
  2. иначе `накладные минуты + расстояние / скорость квантума`;
  3. если расстояние неизвестно — время неизвестно, UEC/час не показывается,
     при сортировке по UEC/час такое направление идёт в конец.
- UEC/час = прибыль / время.

Сортировка по умолчанию — UEC/час, переключается на ROI. Показывается до 5
направлений (число в настройках). Направления с неположительной прибылью
отбрасываются.

Фильтр системы из настроек применяется к обеим точкам. Значение «все»
разрешает маршруты между системами.

### 8.5. Ситуации

- **Отсюда** — `routesFrom(origins)`. Точки закупки: текущий терминал; с
  переключателем «искать и рядом» — ещё и терминалы той же планеты. Для
  соседних точек к времени добавляется пустой перелёт
  (`накладные минуты пустого перелёта + расстояние / скорость`).
  Кнопка «Новый маршрут» и подсказки после ввода цен на закупке — один и тот же
  расчёт; разница только в том, что после ввода цены на точке свои и горячие.
- **Сюда** — `routesTo(destination)`: по товарам, которые точка покупает, —
  откуда их выгоднее везти.
- **Продать или лететь дальше** — `sellOrContinue`. Доступно, когда в трюме
  есть груз и введена реальная цена продажи на текущей точке. Показывает:
  - «здесь сейчас»: прибыль, ROI и UEC/час рейса, если продать здесь
    (делитель — фактически прошедшее время);
  - до 3 альтернатив: ожидаемая и худшая UEC/час рейса с учётом уже
    прошедшего времени и оценки перелёта дальше.
  Считается отдельно по каждому товару в трюме. Решение принимает игрок.

### 8.6. Рейс

- Начинается первой записью «Купил» при отсутствии активного рейса.
- Груз вычисляется из событий: купленное минус проданное по каждому товару;
  цена закупки — средневзвешенная.
- Продавать можно частями и на разных точках.
- Завершается автоматически, когда после продажи груз стал нулевым
  (`done`, конец = время последней продажи), либо вручную кнопкой «Груз
  потерян» (`lost`, конец = момент нажатия).
- Каждая сделка дополнительно пишет наблюдение с той же ценой.
- Отметки «взлетел» и «прилетел» необязательны.

Показатели рейса: вложено, выручка, прибыль, ROI, длительность, UEC/час.

Простой рейс — один товар, одна точка закупки, одна точка продажи. Если у
простого рейса ровно по одной отметке «взлетел» и «прилетел» в правильном
порядке, длительность делится на погрузку (покупка → взлёт), полёт (взлёт →
посадка) и разгрузку (посадка → последняя продажа). Иначе есть только общее
время.

### 8.7. Статистика

- **Мои маршруты** — простые рейсы со статусом `done`, сгруппированные по
  (точка закупки, точка продажи, товар): число рейсов, медианная длительность,
  медианы фаз при наличии, суммарная прибыль, средний ROI,
  UEC/час = суммарная прибыль / суммарное время. Сортировка по UEC/час.
- **Сессия** — цепочка записей дневника без пауз длиннее 2 часов. Итог сессии:
  суммарная прибыль рейсов / время от первой записи до последней. Сюда входят
  пустые перелёты и потерянные рейсы.

### 8.8. Поиск и ввод

- Товар и локация ищутся с первых букв без учёта регистра: сначала совпадение с
  началом кода, затем с началом слова в названии, затем подстрока. Среди
  равных выше те товары, которыми торгует текущая точка. `Enter` берёт верхний
  вариант. Трёх букв обычно хватает; когда они не уникальны (например, `AGR`),
  выбор делается стрелками.
- Цена — целое число UEC за SCU; пробелы и разделители игнорируются.
- Если цена меньше половины исторического минимума UEX или больше удвоенного
  максимума, строка подсвечивается с текстом «проверь цифру». Сохранение не
  блокируется.

## 9. Интерфейс

Язык интерфейса — русский. Названия товаров и локаций — английские, как в игре.

Шапка панели: текущая локация (меняется поиском), корабль и SCU, система,
возраст данных UEX, кнопка «Сменил сервер». Текущая локация — последний
терминал, где вводились цены или была сделка.

Вкладки:

1. **Терминал** (основная).
   - Быстрая строка: код → сторона → цена → SCU → `Enter`. Принимает любой
     товар и любую локацию, в том числе не текущую.
   - Таблица товаров точки: код, название, цена покупки, цена продажи, SCU,
     плашка источника и температуры. Серым — подсказка UEX, обычным текстом —
     свои значения. Переход между полями — `Tab`.
   - Действия по строке: «Купил», «Продал» с указанием количества.
   - Блок подсказок: «Отсюда», «Сюда»; при грузе в трюме сверху — «Продать
     здесь или лететь дальше».
   - Кнопка «Новый маршрут» и переключатель «искать и рядом».
2. **Рейс** — текущий рейс (груз, таймер, отметки, «Груз потерян») и история
   рейсов и сессий.
3. **Маршруты** — таблица «Мои маршруты».
4. **Настройки** — корабль (из списка UEX, SCU подставляется и редактируется),
   система (все или одна), бюджет, пороги температуры, скорость квантума
   (тыс. км/с, по умолчанию 200), накладные минуты (по умолчанию 12, для
   пустого перелёта 5), число подсказок, хоткеи, сторона и ширина панели,
   положение полоски, прозрачность, показ полоски, уровень логирования,
   «Открыть папку логов», «Обновить справочник», «Выход».

Каждая цена в интерфейсе подписана источником и возрастом: «моя · 40 мин»,
«UEX · 2 д». Цвета плашек: горячая, тёплая, остывает, холодная/UEX.

## 10. Надёжность

- Таймер рейса — это разница между `now` и временем в базе, поэтому
  перезапуск приложения рейс не ломает.
- Миграции схемы версионируются; перед миграцией делается резервная копия.
- Ошибки сети и разбора ответов UEX не всплывают сырым текстом: в шапке
  показывается «UEX недоступен, данные от …».

## 11. Логирование

Полное логирование включено с первого этапа и по умолчанию работает на уровне
`debug`. Цель — по одному файлу лога восстановить, что делал игрок, что
ответил UEX и почему приложение показало именно эти цифры.

Механизм: `tauri-plugin-log`. В один файл пишут и Rust, и интерфейс. Файлы
лежат в подкаталоге `logs/` каталога данных, ротация по размеру (5 МБ),
хранятся последние пять. Уровень (`debug`, `info`, `warn`, `error`) меняется в
настройках без перезапуска.

Формат строки: время с миллисекундами, уровень, модуль, сообщение, контекст в
JSON. Каждый запуск начинается строкой с версией приложения, версией Windows,
размером экрана и номером версии схемы базы.

Что пишется:

| Область | События |
|---|---|
| Окно | смена состояния полоска/панель, потеря и получение фокуса, изменение размера и положения |
| Хоткеи | регистрация (успех или причина отказа), каждое срабатывание |
| UEX | каждый запрос: адрес, код ответа, длительность, число строк; ошибки сети и разбора; начало и конец каждой синхронизации, сколько пачек прошло |
| База | миграции, резервные копии, каждая запись в дневник и в настройки вместе с записанными значениями; запросы длиннее 200 мс |
| Расчёты | на каждый показ подсказок: входные точки и фильтры, число кандидатов до и после отсева, итоговый список с ценами, источниками и температурой; для «продать или лететь дальше» — все сравниваемые варианты |
| Рейс | старт, каждая сделка, отметки, автозавершение, «груз потерян» |
| Действия | нажатия кнопок и команды интерфейса, смена вкладки, смена текущей локации |
| Сбои | необработанные исключения и отклонённые промисы в интерфейсе, паники Rust — со стеком |

Правила:

- `core` остаётся чистым и сам ничего не пишет. Функции расчёта возвращают
  вместе с результатом трассировку (сколько кандидатов отброшено и по какой
  причине), а пишет её вызывающий слой.
- Логгер — интерфейс, который передаётся в `data`, `platform` и `ui`. В тестах
  подставляется логгер в памяти, по нему проверяется, что сбои попадают в лог.
- Ошибка записи лога никогда не ломает работу приложения.

В настройках есть кнопка «Открыть папку логов».

## 12. Тестирование

- `core` — модульные тесты на каждую функцию: границы температур, «сменил
  сервер», цепочка запасных значений оценки, объём с неизвестными величинами,
  сортировки, худший случай, вычисление груза, автозавершение рейса, фазы,
  группировка маршрутов, границы сессий, поиск, разбор цены.
- `data` — репозитории и миграции на `better-sqlite3` в памяти; клиент UEX и
  синхронизация — на сохранённых ответах API, включая сбой посреди пачек.
- Вручную, в игре: окно поверх игры в borderless, прохождение кликов сквозь
  полоску, хоткеи при фокусе в игре, возврат фокуса по `Esc`.

## 13. Этапы

1. **Каркас и риск.** Проект Tauri, окно с двумя состояниями, хоткей, трей,
   логирование. Сразу проверяется в игре — это единственное, что нельзя
   проверить тестами.
2. **Данные.** Схема, миграции, клиент UEX, синхронизация, настройки, резервные
   копии.
3. **Дневник и подсказки.** Вкладка «Терминал», ввод, температура, оценки,
   «Отсюда», «Сюда», «Новый маршрут».
4. **Рейсы.** Сделки, таймер, отметки, «продать или лететь дальше», полоска с
   живыми данными.
5. **Статистика.** «Мои маршруты», сессии, история.

## 14. Поправки

### 14.1. UEX через замедленную сеть (2026-10-07)

Во время реализации выяснилось: в сети пользователя ответ от `api.uexcorp.uk`
обрывается примерно на 24 КБ, меньшие ответы приходят нормально. В другое
время того же дня ограничения не было, поэтому приложение должно работать в
обоих случаях. Раздел 6 меняется так:

- Сжатие ответов (gzip, brotli) обязательно. Без него даже цены одного
  терминала не помещаются в лимит.
- Таймаут запроса — 15 секунд.
- Терминалы запрашиваются по одной живой системе за запрос
  (`terminals?type=commodity&id_star_system=…`).
- Корабли запрашиваются по одному производителю за запрос: список
  производителей из `companies?is_vehicle_manufacturer=1`, затем
  `vehicles?id_company=…`. Сбой загрузки кораблей не срывает синхронизацию
  справочника: SCU можно ввести вручную.
- Цены запрашиваются пачками по 2 терминала (около 70 запросов на полное
  обновление). Пачка, которая не загрузилась, повторяется по одному терминалу.
- Все запросы к UEX идут последовательно.
- Запрос расстояний от точки (`commodities_routes`) для крупных хабов может не
  пройти; тогда расстояния добираются попарно, а повторная попытка для этой
  точки делается не раньше чем через сутки.

### 14.2. Поиск «где купить» и «где продать» для любой станции (2026-10-07)

Новый сценарий: игрок вводит любую станцию, товар и цену, которую видит, и
одним действием узнаёт, где этот товар закупить дешевле всего (если станция
его покупает) или где продать дороже всего (если станция его продаёт), сразу
с ROI, временем и UEC/час.

- В разделе 8.5 «Сюда» и «Отсюда» принимают необязательный фильтр по товару.
- Вкладка «Терминал» показывает *просматриваемую точку*. Она отделена от
  *текущей локации* (где стоит корабль). Ввод цены для удалённой станции
  текущую локацию не меняет. Текущая локация меняется кнопкой «Я здесь» и
  сделкой.
- После ввода цены через быструю строку блок подсказок сам переключается на
  нужный поиск: цена продажи → «Где купить», цена закупки → «Где продать».
- В каждой строке таблицы есть те же два действия, в том числе для цен,
  известных только из UEX.
- Для удалённой точки без активного рейса в расчёт идёт полный объём корабля.

### 14.3. Таймер количества (2026-10-07)

Количество товара на точке меняется со временем: склад пополняется, спрос
восстанавливается. Приложение ведёт собственную оценку «сколько там сейчас».

Что известно о механике (поиск по открытым источникам, не проверено на текущем
патче): пополнение идёт понемногу раз в минуту, скорость у каждой пары «точка +
товар» своя; единственный найденный пример — Agricium, 38 единиц в минуту до
потолка 2 800, то есть с нуля до полного около 74 минут.

Правила:

- Количество в своём наблюдении: пусто — неизвестно, **ноль — известно, что
  пусто**. (Для данных UEX ноль по-прежнему означает «неизвестно».)
- Сделка пишет в дневник остаток после сделки: было 340, купил 300 → 40.
- Оценка сейчас = `min(максимум, база + скорость × прошедшие минуты)`, вниз до
  целого. База — количество из последнего своего не холодного наблюдения.
- Максимум — наибольшее из: самого большого количества, которое игрок сам
  видел на этой паре, и максимума UEX (за неделю, иначе за всё время). Если
  база больше максимума, максимумом считается база.
- Скорость (в минуту) выучивается по своим замерам на этой паре: для двух
  соседних замеров с разницей не меньше 2 минут, где количество выросло,
  скорость = прирост / минуты; берётся наибольшая из наблюдавшихся (чужие
  покупки между замерами только занижают).
- Пока скорость не выучена: `максимум / время полного восстановления`, время
  задаётся в настройках, по умолчанию 75 минут. Нет ни скорости, ни максимума —
  оценка равна базе.
- Модель одна и та же для остатка на закупке и для спроса на продаже.
- Своё холодное количество не используется: берётся количество UEX.
- Оценка идёт в расчёт объёма (раздел 8.3). Известный ноль ограничивает объём.
- В интерфейсе оценка показывается как «≈ 250» с пояснением «было 40 · 20 мин»
  и пометкой, выучена скорость или взята запасная.

### 14.4. Управление мышью вместо хоткеев (2026-10-07)

Проверка в игре (диагностическая сборка, запись сессии пользователя) показала:

- Глобальные хоткеи Windows (`RegisterHotKey`) в Star Citizen не срабатывают
  ни разу, пока игра активна. Низкоуровневый перехват клавиатуры срабатывает.
- Клик по окну поверх игры доходит до оверлея, когда игра показывает курсор.
- Когда панель получает фокус, игра считает себя неактивной (звук пропадает,
  если в игре не включён звук в фоне). Клик по игре возвращает управление.

Раздел 4 меняется так:

- **Плашка** (бывшая «полоска») кликабельна и не берёт фокус: клик по ней
  открывает панель, но сам по себе игру не прерывает. Клики сквозь неё больше
  не проходят, поэтому она маленькая и стоит в углу.
- **Панель** открывается с той же стороны экрана, где стоит плашка, чтобы
  курсор сразу был над ней.
- **Панель сворачивается сама**, когда теряет фокус (игрок кликнул по игре),
  а также по крестику и по `Esc`. Фокус при этом насильно не возвращается.
- **Клавиши необязательны** и по умолчанию не назначены: панель, «взлетел»,
  «прилетел». Назначенные клавиши ловятся низкоуровневым перехватом. Перехват
  смотрит только на назначенные клавиши, никакие другие не читает и не пишет в
  лог, и никогда не «съедает» нажатие — игра получает его тоже.
- **Кнопки «Взлетел» и «Прилетел»** есть на плашке во время рейса.
- **Монитор**: окно всегда ставится на основной монитор, независимо от того,
  откуда запущено приложение.
- `tauri-plugin-global-shortcut` больше не используется.
- **Диагностика**: если рядом с exe лежит файл `portable.flag`, копия лога
  дополнительно пишется в файл рядом с exe.

### 14.5. На вкладке продажи показан склад покупателя, а не спрос (2026-10-07)

Скриншоты терминала показали, как на самом деле устроены две вкладки:

- **«Купить»** (магазин продаёт): название, уровень запаса текстом, «Количество
  в магазине N SCU», цена за SCU. Здесь N — сколько можно купить.
- **«Местный спрос»** (магазин покупает): название, уровень запаса текстом,
  «N SCU», цена за SCU и допустимые размеры контейнеров. Здесь N — сколько
  этого товара **уже лежит у магазина** («0 SCU, нет в наличии» — магазин пуст и
  платит хорошо), а не сколько он готов купить. Сколько он готов купить, игра
  не показывает.

То же подтверждают данные UEX: количество на стороне продажи равно нулю в 88%
строк, и почти все они имеют уровень «нет в наличии».

Поэтому разделы 8.2, 8.3 и 14.3 меняются:

- Количество в наблюдении на стороне продажи — это склад покупателя. Оно
  сохраняется и показывается как справка («у покупателя на складе N SCU»).
- **Объём рейса спросом не ограничивается**: объём = минимум из свободного
  места, остатка на закупке и бюджета. Ноль на стороне продажи рейс не
  отменяет.
- Таймер количества (14.3) работает только для стороны закупки. На стороне
  продажи количество показывается как записано, без пересчёта во времени.
- Продажа пишет в дневник склад покупателя после сделки: было N, продал X →
  N + X.
- В «продать здесь или лететь дальше» объём не ограничивается количеством на
  точке: сравнение идёт на весь груз, частичная продажа остаётся возможной.

### 14.6. Количество и цена — независимые замеры (2026-10-07)

Игрок часто поправляет только цену, не трогая количество. Такое наблюдение
не должно стирать то, что известно о количестве.

- Наблюдение без количества означает «в этом замере количество не указано», а
  не «количество теперь неизвестно».
- Для количества берётся последнее своё наблюдение по этой паре и стороне, в
  котором количество указано, — даже если после него были наблюдения только с
  ценой. Его температура считается по его собственному времени.
- Таймер запаса (14.3) отсчитывается от этого замера.
- Возраст данных UEX может быть неизвестен; тогда цена подписывается просто
  «UEX», без возраста.

### 14.7. Окно в духе PolitBuro: мини-строка, развёрнутый вид, без пустот (2026-10-07)

Первая сборка интерфейса пользователю не понравилась. Его слова: «хочу
концепцию интерфейса, как мы делали в PolitBuro — с минимальным интерфейсом во
время рейса и развёрнутым, когда пользуюсь, по стилю близким к игре, хай-тек»
и «пустых мест быть не должно, экономим место; любое дополнительное место
должно быть выдвижным». Раздел 9 и пункты 14.4 про плашку и панель заменяются
этим разделом. Всё остальное в 14.4 (клавиши необязательны, перехват смотрит
только на назначенные клавиши, основной монитор, диагностика) остаётся.

**Окно и игра**

- Окно никогда не забирает фокус у игры само. Кнопки, строки таблиц, секции
  нажимаются мышью, а игра остаётся активным окном: не замирает и не теряет
  звук.
- Клавиатуру окно берёт только на то время, когда она нужна: игрок кликнул в
  поле ввода или в выпадающий список. В этот момент запоминается окно, у
  которого был фокус. Когда ввод закончен (`Esc`, клик мимо поля, поле
  исчезло), окно снова перестаёт брать фокус и возвращает его запомненному
  окну. Если игрок сам кликнул по игре, фокус уже у неё — насильно ничего не
  возвращается.
- `Enter` в строке быстрого ввода сохраняет запись и оставляет клавиатуру у
  окна: игрок вводит цены подряд. `Esc` отдаёт клавиатуру игре, окно остаётся
  развёрнутым.
- Защита от зажатой клавиши игры (буква не должна «протечь» в поле) остаётся.

**Два состояния**

- **Мини-строка** — одна строка высотой около 26 px в выбранном углу экрана,
  шириной по содержимому. Без рейса: локация и свежесть данных. В рейсе:
  таймер, груз, цель, ожидаемая цена продажи, ожидаемый доход в час и одна
  кнопка следующей отметки («Взлетел» / «Прилетел»), которая нажимается без
  разворачивания. Клик по остальной строке разворачивает окно.
- **Развёрнутый вид** — то же окно в том же углу, шириной из настройки (по
  умолчанию 440 px) и высотой ПО СОДЕРЖИМОМУ, не выше экрана минус поля. Когда
  содержимое не помещается, прокручивается длинная секция, а не окно.
- Разворачивание — по клику (и по назначенной клавише, если она есть).
  Сворачивание — кнопкой и само, когда курсор ушёл с окна и прошло время из
  настройки (по умолчанию 40 с; 0 — не сворачивать само). Пока клавиатура у
  окна или открыт диалог сделки, окно само не сворачивается.

**Без пустот**

- В окне нет областей фиксированной высоты, нет вкладок-заглушек и поясняющих
  абзацев. Нет данных — нет блока; пустой список — одна приглушённая строка.
- Развёрнутый вид — это шапка и столбик **секций**. У секции строка-заголовок
  высотой 24 px: стрелка, название, краткая сводка, действия. Клик по
  заголовку выдвигает или убирает содержимое; состояние каждой секции
  запоминается между запусками.
- Секции: «Рейс» (есть только когда идёт рейс или в трюме груз), «Терминал»
  (таблица просматриваемого терминала; строка быстрого ввода выдвигается
  кнопкой в заголовке), «Варианты» (есть только когда есть ответ поиска или
  «нового маршрута»; закрывается крестиком), «Мои маршруты» (лучшие маршруты,
  история, сессии). Настройки открываются кнопкой в шапке и занимают окно
  целиком; группы настроек — тоже секции.
- Шапка — одна строка: локация (клик превращает её в поиск), свежесть данных
  UEX, «Новый маршрут», настройки, свернуть.
- Строки таблиц однострочные, высотой 22 px. Клик по строке выдвигает под ней
  вторую строку: поля цены и количества и действия для этой строки («Где
  купить», «Где продать», «Купил», «Продал», «Цель»). Одновременно выдвинута
  одна строка на таблицу.
- Свежесть цены показывается цветной меткой рядом с числом (горячая, тёплая,
  остывающая, холодная; данные UEX — пустая рамка), а возраст и источник —
  в подсказке и в выдвинутой строке. Свои значения — обычным текстом, чужие и
  остывшие — приглушённым.
- В списке вариантов видны оба конца рейса, когда место покупки отличается от
  просматриваемого терминала, и отмечена текущая цель.
- Ответ поиска появляется НИЖЕ таблицы терминала, чтобы строки не уезжали
  из-под курсора.

**Вид**

- Тёмное «стекло» с холодным оттенком, тонкие линии, срезанные углы у окна и
  основных кнопок, один акцентный цвет (циан), без скруглений, теней и
  свечения. Заголовки секций — мелкие, прописными, с разрядкой.
- Шрифт — узкий технический, который уже есть в Windows (Bahnschrift), с
  запасным Segoe UI; цифры одинаковой ширины и выровнены вправо.
- Все цвета, отступы и размеры — через общие переменные темы.

**Проверка вида**

- Интерфейс открывается в обычном браузере с подменой слоя Tauri и тестовыми
  данными; одной командой снимается снимок любой сцены. Перед тем как отдать
  сборку пользователю, каждый экран просматривается на снимке.

Новые настройки: `idleCollapseSec` (40), `openSections` (какие секции
выдвинуты). `panelWidth` по умолчанию 440. `showStrip` означает «показывать
мини-строку»: если выключено, свёрнутое окно скрыто и открывается из трея или
клавишей.

### 14.8. Правки после теста в игре (2026-10-07)

Пользователь проверил сборку с вкладкой «Терминал» в игре. Его замечания и
то, что из них следует. Где этот раздел расходится с 14.2 или 14.7 — действует
он.

**Окно можно двигать.** «Хочу перемещать это окно, это удобнее: зацеп + лок».

- У окна есть зацеп: за него окно перетаскивается мышью. Перетаскивание не
  забирает фокус у игры.
- Положение запоминается как угол экрана и отступы от него. Окно растёт и
  сжимается от этого угла и не выходит за экран.
- Есть замок: пока он закрыт, зацеп не действует.
- Выбор угла в настройках ставит окно в этот угол с обычным отступом.

**Товары терминала — по сторонам, а не в одной куче.** «На Terra Gateway я
могу купить 7 ресурсов, а скупают они куда больше. Не должно быть оно всё в
куче».

- Секция «Терминал» показывает одну сторону за раз, как две вкладки торгового
  терминала в игре: «Купить здесь · N» и «Продать здесь · N».
- Столбцы: товар, цена, минимум–максимум, количество.

**Цены вводятся молча; маршруты — по кнопке.** «Просто вбиваю актуальные
цены. При нажатии кнопки — маршрут — получаем 5 путей».

- Запись цены больше НЕ запускает поиск сама и ничего не сдвигает на экране.
- «Маршрут» в шапке даёт лучшие варианты из текущей локации (число из
  настройки, по умолчанию 5).
- У выдвинутой строки товара остаются свои кнопки: «Где продать» на стороне
  покупки, «Где купить» на стороне продажи.

**Варианты читаются с одного взгляда.** «Куча текста — мало понятно. Цена
продажи одна — нам бы видеть минималку и максималку. Я должен по цвету
понимать потенциальный ROI».

- Вариант — одна строка: место (оба конца рейса, когда покупать надо не там,
  где открыт терминал), цена на другом конце, её минимум–максимум, ROI, доход
  в час. Никаких предложений внутри строк; подробности — в выдвинутой строке.
- ROI показан цветом: полоса у левого края строки и само число. Ступени:
  от 30 % — отлично, от 15 % — хорошо, от 5 % — так себе, от 0 — слабо,
  ниже нуля — убыток.
- Секцию «Варианты» закрывает заметный крестик в её заголовке; таблица товаров
  при этом остаётся на месте (варианты стоят под ней).

**Ответ сразу, уточнение потом.** В тесте поиск «Сюда» около девяти секунд по
одному запрашивал расстояния у UEX и выглядел как зависание.

- Подсказка сначала показывается по тому, что уже есть в локальных данных, и
  помечается как предварительная, пока расстояния докачиваются; виден счётчик
  («расстояния 7/15»). Когда расстояния получены, список обновляется.
- Расстояния хранятся бессрочно, поэтому второй раз ответ окончательный сразу.

Новые настройки: `windowDx`, `windowDy` (отступы окна от угла, по умолчанию
16), `windowLocked` (замок, по умолчанию выключен).

### 14.9. Правки после теста нового окна (2026-10-07)

Пользователь проверил сборку с новым окном. Его замечания: «Для смены сервера
нужен апрув», «Я поставил цель — а что толку? Где она отображается? Как цель
убрать?», «Где мне таймер завести погрузки и выгрузки?».

**Смена сервера — с подтверждением.** Один случайный клик делает все свои
цены холодными.

- Кнопка «Сменил сервер» сначала спрашивает строкой под шапкой: «Сервер
  сменился? Свои цены до этой минуты станут холодными.» — «Да, сменился» /
  «Отмена». Без ответа вопрос исчезает сам и считается отменой.
- Тем же способом подтверждается «Груз потерян».

**Цель видна сразу и снимается там же, где видна.**

- Секция «Рейс» есть, когда идёт рейс ИЛИ выбрана цель. С целью и без рейса
  она в состоянии «план»: «цель: ARC-L1», крестик «Снять цель» и одна строка
  «Таймер пойдёт с первой покупки».
- Мини-строка без рейса показывает «HUR-L1 → ARC-L1», когда цель выбрана.
- Нажатие «Цель» в вариантах открывает секцию «Рейс». В подробностях варианта,
  который уже является целью, кнопка называется «Снять цель».

**Погрузка, полёт, выгрузка — видимые таймеры.**

- Таймер рейса запускается сам с первой покупки. Отдельно заводить его не
  нужно.
- Рейс делится на фазы: погрузка — от покупки до «Взлетел»; полёт — от
  «Взлетел» до «Прилетел»; выгрузка — от «Прилетел» до продажи груза.
- Мини-строка в рейсе начинается с текущей фазы и её собственного времени
  («ПОГРУЗКА 03:12», «ПОЛЁТ 08:40», «ВЫГРУЗКА 02:05»); рядом одна кнопка
  следующей отметки. Общее время рейса — в подсказке и в секции «Рейс».
- Секция «Рейс» показывает три фазы текущего перелёта с их длительностью и
  общее время.
- Длительности фаз завершённых рейсов идут в статистику маршрутов.

### 14.10. Что везти сюда, продажа без закупки, заработок за сессию (2026-10-07)

Сценарий пользователя: «Я прилетел на Lorville — CBD. Там для покупки только
Waste, всё остальное в продажу. Допустим, я отмечу пару цен. Но у нас же нет
кнопки „что сюда привезти“. После указанных цен прямо там, в продажах, надо
миганием или иным способом пометить: вот этот товар потенциально нужно сюда
привезти, и есть места, где его можно купить с выгодой от 50 % (ROI)». И:
«Продал Medical Supplies — надо, чтобы софтина тоже считала сумму и хранила её
где-то: заработанные за сессию».

**Выгода видна прямо в таблице терминала.**

- У каждой строки таблицы есть лучший ROI для этого товара: на стороне
  «Продать здесь» — лучший из вариантов «купить где-то и привезти сюда», на
  стороне «Купить здесь» — лучший из вариантов «купить здесь и отвезти
  куда-то». Считается по локальным данным, без запросов к UEX; пересчитывается,
  когда меняются цены или просматриваемый терминал.
- ROI стоит в строке отдельным столбцом, цветом своей ступени (как в списке
  вариантов). Строка с ROI не ниже порога из настройки (по умолчанию 50 %)
  выделена цветной полосой слева; когда строка впервые переходит порог после
  ввода цены, она один раз мягко вспыхивает. Постоянного мигания нет.
- Клик по ROI в строке открывает «Варианты» для этого товара: где купить
  (сторона продажи) или куда везти (сторона покупки).
- В заголовке секции «Терминал» есть кнопка общего поиска по просматриваемому
  терминалу: «Что везти сюда» на стороне продажи и «Куда везти отсюда» на
  стороне покупки — лучшие варианты по всем товарам.

**Продажа без закупки.** Товар мог быть куплен до запуска программы, добыт
или собран.

- «Продал» для товара, которого нет в учтённом трюме, не отказывает, а
  записывает продажу как доход без закупки: количество вводит игрок,
  вложение 0, прибыль равна выручке, ROI не показывается.
- Такая запись не трогает идущий рейс, попадает в историю («продажа без
  закупки») и в заработок сессии, но не в рейтинг маршрутов и не в медианы
  времени.

**Заработок за сессию виден всегда.**

- Текущая сессия — последняя, если с её последней записи прошло меньше
  перерыва между сессиями (2 часа).
- Её прибыль показана в мини-строке без рейса («сессия +1,24M») и в сводке
  секции «Мои маршруты» вместе с доходом в час.

**Цены обновляются вручную.** Надпись о свежести UEX в шапке — кнопка: она
запускает обновление цен сейчас и показывает его ход.

Новая настройка: `roiHighlightPct` (порог выделения строки, 50).

### 14.11. Итоги общей проверки ветки (2026-10-07)

Перед первым выпуском ветку проверили целиком четыре проверяющих: оболочка и
безопасность, стыки задач в состоянии приложения, отложенные замечания, сверка
с этой спецификацией. Ниже — что изменилось в правилах и что в старых разделах
больше не верно. Более поздняя запись сильнее ранней.

**Окно и клавиатура.**

- Окно никогда не просит у Windows фокус способом, при котором в поток ввода
  может уйти синтетическое нажатие. Вызов `setFocus` из Tauri не используется
  совсем (в оконной библиотеке он при отказе Windows посылает нажатие Alt), и
  право на него убрано. Своя команда просит фокус один раз и ничего больше не
  делает.
- Пока указатель над текстовым полем, окно «взведено»: оно становится
  активируемым, и нажатие игрока активирует его обычным порядком. Указатель
  ушёл — окно снова не активируемое.
- Если Windows отказала в фокусе, поле не считается занятым: держателя нет,
  следующее нажатие активирует окно само.
- Активация, о которой никто не просил (нажатие мимо поля сразу после ухода с
  него, закрывшееся активное окно), сразу отдаётся обратно тому окну, у
  которого был фокус.
- Запуск второй копии показывает окно первой и завершается.
- После ошибки запуска окно развёрнуто с текстом ошибки и не сворачивается по
  простою, даже если мини-строка выключена.
- Назначенные клавиши применяются заново при каждом разворачивании окна мышью
  или из трея: перехват, который Windows сняла, возвращается сам.

**Локация и рейс.**

- Текущую локацию меняют «Я здесь» и успешная сделка (в том числе продажа без
  закупки). Сделка не меняет просматриваемый терминал и сторону таблицы.
- «Продать здесь или лететь дальше» считается для ПРОСМАТРИВАЕМОГО терминала,
  а не для текущей локации (поправка к 8.5): свежая своя цена продажи есть
  только там, где игрок стоит и смотрит, а текущей локацией до продажи
  остаётся точка закупки.
- Планы — «Маршрут», поиски, ROI в строках таблицы — считаются на полный трюм
  (поправка к 8.3 и 14.2): с грузом на борту после прилёта все списки иначе
  были бы пустыми. На свободное место считается только форма покупки.
- Ожидаемый доход в час показывается, только когда известно время рейса:
  известно время полёта от места первой закупки до цели, либо последняя
  отметка — «Прилетел». Иначе числа нет; прибыль «≈» показывается. Мини-строка
  и карточка рейса показывают одно число, по всему рейсу.
- После сделки остаток на складе записывается от своего количества, которое
  показывает строка, включая оценку таймера пополнения (14.3: «было 340,
  купил 300 → 40»). Количество UEX по-прежнему не берётся; в редактируемой
  ячейке оценка по-прежнему не сохраняется как введённая.
- Когда рейс закончен или груз потерян, цель снимается.
- Полузаписанный рейс чинится при запуске и перед каждой сделкой: активный
  рейс без событий удаляется; активный рейс, в котором всё продано, закрывается
  временем последней продажи.

**UEX.**

- Между началами запросов не меньше 0,5 с.
- Серия запросов прекращается после трёх сетевых сбоев подряд или трёх пакетов
  подряд, не давших ничего, какой бы ни была причина; ответ 429 прекращает
  серию сразу. Оставшиеся терминалы считаются необновлёнными. Пакет, упавший
  по сети, по одному терминалу не повторяется (поправка к 14.1: повтор по
  одному остаётся для отказа сервера на пакет).
- Неудачное обновление справочника повторяется вместе со следующим обновлением
  цен.
- Цены UEX терминалов, которые справочник больше не помечает живыми, не
  загружаются; свои записи по ним остаются.
- При первой загрузке цен таблица наполняется по ходу, а не в конце.
- При недоступном UEX шапка показывает возраст данных: «UEX офлайн 3 ч».
- Перенаправления HTTP разрешены только внутри `https://api.uexcorp.uk/`.
  Cookie не хранятся.

**База и резервные копии.**

- Порядок запуска: открыть базу → проверить версию схемы → слить журнал в
  файл базы → резервная копия → миграции → починка рейсов. Только что
  созданная база не копируется.
- База от более новой версии программы не открывается: запуск останавливается
  с сообщением, резервная копия при этом не делается.
- База работает в режиме журнала: рядом с `sctrade.db` лежат `-wal` и `-shm`,
  это части базы.

**Лог (поправки к разделу 11).**

- Логи лежат в `%LOCALAPPDATA%\com.sctrade.app\logs`, база и копии — в
  `%APPDATA%\com.sctrade.app`; это разные папки.
- Строки сторонних библиотек пишутся только уровня `info` и выше, какой бы
  уровень ни был выбран.
- В логе нет номеров чужих процессов (раньше модуль возврата фокуса писал
  номер процесса окна, у которого была клавиатура). Номер окна остаётся.
- Слежение за курсором — диагностика; оно работает, только если рядом с exe
  лежит файл `cursor-watch.flag`.
- Отклонённый ввод логируется без того, что было набрано.

**Что в спецификации устарело без отдельной поправки.**

- 14.8: переключатель сторон подписан «Купить · N» / «Продать · N».
- 14.7: в мини-строке без рейса — локация, цель и заработок сессии; свежесть
  данных UEX показана в шапке развёрнутого окна. Кнопка «Новый маршрут»
  называется «Маршрут»; в шапке есть ещё замок и «Сменил сервер».
- 8.2: своя холодная цена, для которой у UEX нет строки, всё же возвращается
  как оценка (другой нет).
- 8.7: сессии режутся по своим наблюдениям и событиям рейсов, отметки
  «Взлетел» / «Прилетел» в том числе.

**Отложено решением, не сделано.**

- CSP для окна: пути от данных UEX или набранного текста к выполнению скрипта
  нет, а ошибка в CSP — пустое окно у всех, и проверить это запуском из сессии
  разработки нельзя.
- Автоматическая догрузка расстояний для «продать здесь или лететь дальше»
  (запрос к UEX, о котором игрок не просил).
- Строка в логе на каждый пересчёт ROI в строках таблицы.

### 14.12. «Прилетел» показывает терминал цели (2026-10-07)

Просьба пользователя: «Давай автоматически менять место терминала исходя из
цели: если я приземлился на станции из цели, то и сверху давай менять
терминал, чтоб я сразу видел всё местное».

- Отметка «Прилетел» (кнопка в секции «Рейс», кнопка мини-строки или
  назначенная клавиша) при заданной цели делает терминал цели текущей
  локацией и показывает его в шапке и в секции «Терминал».
- Если в трюме есть груз, таблица открывается стороной «Продать»; если на этой
  стороне у терминала нет строк — действует обычное правило выбора стороны.
- Без цели отметка ничего не переключает. Если игрок сел не там, он выбирает
  терминал в шапке сам; продажа всё равно поставит локацию по месту сделки.
- Цель при этом не снимается: она снимается, когда рейс закончен или груз
  потерян (14.11).

Поправка к 14.11: текущую локацию меняют «Я здесь», успешная сделка и отметка
«Прилетел» при заданной цели.

### 14.13. Правка цены и количества в строке; где находится терминал (2026-10-07)

Замечания пользователя после проверки: «Отдельно не правится количество,
приходится и цену трогать, даже если она такая же. Изменение цены идёт, если
заново полностью ввожу цифру, а я бы хотел её править. При выборе станции не
ясно, где она (условный пример — Stanton Gateway: их много, и они в разных
системах)».

**Поля раскрытой строки таблицы.**

- В поле цены всегда стоит та цена, которую показывает строка: своя (любой
  свежести) или справочная UEX. Её можно поправить, а не набирать заново.
  Чужая (не своя) цена в поле выглядит приглушённо, пока её не тронули.
- Количество правится отдельно: изменено только количество — записывается
  наблюдение с ценой, которая стоит в поле (своей или справочной), и этим
  количеством. Цену трогать не нужно. Если цены нет совсем (ни своей, ни UEX),
  поле цены по-прежнему обязательно.
- Набранная цена записывается, даже если она равна справочной: игрок её
  подтвердил. Своя цена, набранная без изменения, новой записи не даёт.
- `Enter` в любом из двух полей — «я это вижу сейчас»: записывается наблюдение
  с тем, что стоит в полях, даже если ничего не меняли (так справочная цена
  подтверждается как своя, а своя — освежается). Уход из строки кликом
  записывает только изменённое.
- Правило 14.6 в силе: наблюдение без набранного количества — «в этом замере
  количество не указано»; оценка таймера пополнения в поле количества не
  подставляется и как введённая не сохраняется.

**Где находится терминал.**

- В списке поиска локации у каждого варианта приглушённо подписано место:
  система и планета, луна или станция. Искать можно и по названию системы.
- Полное место есть в подсказке у локации в шапке, у заголовка секции
  «Терминал» и у терминала в строке списка вариантов.

### 14.14. Цена закупки в мини-строке, сортировка «Моих маршрутов», очистка истории (2026-10-09)

Просьбы пользователя перед финалом: «В минимальном виде важно показать не
только название ресурса, что мы везём, и его количество, но и его начальную
стоимость: ожидаемую мы знаем, а начальную нужно идти смотреть, а тут сразу
видим. История — сколько она будет копиться и можем ли мы её очистить? А самые
топ-маршруты в маршрутах выдавать вверх, если кликаю по ROI, доходу в час и
т. д.»

**Мини-строка рейса.** У каждого товара в трюме — количество и
средневзвешенная цена закупки: «MEDS 120 SCU по 2 115». Когда товаров
несколько, слово «SCU» опускается, чтобы строка не росла: «MEDS 120 по 2 115,
STIM 80 по 2 810». Если строка всё равно не помещается, груз обрезается
многоточием, а полный список — в подсказке: по каждому товару количество, цена
закупки и ожидаемая цена продажи в точке цели.

**«Мои маршруты» → «Маршруты».** Заголовки числовых столбцов (UEC/ч, число
рейсов, время, прибыль, ROI) — кнопки сортировки: клик ставит лучшие по этому
столбцу сверху, повторный клик переворачивает порядок. Активный столбец
помечен стрелкой. По умолчанию — UEC/ч, как раньше. Выбор живёт до закрытия
программы.

**История рейсов.** Рейсы хранятся бессрочно, пока их не очистят.

- В «Настройки» → «Данные» видно, сколько рейсов в истории и с какой даты, и
  есть две кнопки: «Очистить старше 30 дней» и «Очистить всю историю». Обе
  спрашивают подтверждение с числом рейсов, которые будут удалены.
- Удаляются только завершённые и потерянные рейсы (и продажи без закупки);
  идущий рейс не трогается. Свои цены (дневник) не удаляются.
- После очистки рейтинг маршрутов, сессии и свои медианы времени считаются по
  оставшимся рейсам.
- Резервная копия базы, сделанная при запуске, содержит историю до очистки.

**Списки «Моих маршрутов» не растягивают окно** (просьба пользователя в тот же
день: «История должна показывать последние 8 рейсов, чтобы не занимала много
места вниз, либо 8 рейсов и скролл»). Список каждой вкладки — «История»,
«Маршруты», «Сессии» — не выше восьми строк; остальное прокручивается внутри
списка, шапка таблицы при прокрутке остаётся на месте.

Перед выпуском программу прошёл исполнитель в роли опытного игрока-торговца
(его слово — `.superpowers/test-build/TRADER-REVIEW.md`). Из его замечаний
сделано:

**Рейс и сделки.**

клавиатуру от клика по кнопке); настройка масштаба интерфейса; `Enter` в поле
локации как «Я здесь». Не взято как новые возможности: выгрузка истории,
обратный груз и цепочки, падение цены при большой продаже.

### 14.16. Версия 1.1: всё из «Что мешает» слова «торговца» (2026-10-09)

Пользователь попросил закрыть весь раздел «Что мешает» слова «торговца» и
выпустить версию 1.1 с установщиком в теме целиком. Развилки решал сам
«торговец» (ему были заданы одиннадцать вопросов); одно его предложение не
взято — порог подсветки ROI остаётся 50 % (число пользователя). Этот раздел
отменяет последний абзац 14.15 в части выделения числа, курсора после кнопок,
масштаба и `Enter` в поле локации.

**Ввод и клавиатура.** Свойства 14.7 и 14.11 не изменены: окно берёт
клавиатуру только от нажатия игрока, ничего синтетического в поток ввода не
попадает, Rust-часть и модель держателей не тронуты.

- Числовое поле (цена и количество в строке таблицы, в форме сделки, в быстром
  вводе) выделяет всё число, когда получает курсор — кликом или `Tab`. Клик в
  поле, где курсор уже стоит, ставит курсор в место клика; протяжка первым же
  нажатием оставляет выделенной протянутую часть. Выделение — не ввод:
  черновик не создаётся, приглушённая чужая цена остаётся приглушённой.
- Кнопки, открывающие ввод, ведут себя для механизма клавиатуры как поле: пока
  указатель над такой кнопкой, окно взведено, и нажатие игрока активирует его.
  Таких кнопок четыре: «+ цена» (пока быстрый ввод закрыт), «Купил» и «Продал»
  раскрытой строки, и кнопка подтверждения формы сделки, пока её нажатие только
  спрашивает про цену. Курсор после нажатия встаёт: «+ цена» — в «Товар»;
  «Купил» — в количество; «Продал» — в цену, а если количество пустое (продажа
  без закупки) — в количество. Клик по строке таблицы курсор не ставит. Если
  Windows отказала в клавиатуре, держателя нет, а кнопка делает своё дело.
- Клавиатура возвращается игре сама, тем же путём, что `Esc`, когда окно её
  держит, 15 секунд не было ни клавиши, ни нажатия на поле, и на странице нет
  ничего введённого и не подтверждённого. **Правило, которое это определяет:**
  автоматический возврат никогда не становится причиной записи и никогда —
  причиной потери того, что игрок ввёл и не подтвердил; в сомнении клавиатура
  остаётся у окна. Запоминается поле, что в нём стояло до ввода и что игрок
  ввёл. `Enter`, `Esc` и уход из поля считаются подтверждением только там, где
  компонент в этот момент сам сохраняет или отбрасывает ввод, и страница это
  помечает: ячейка таблицы (`data-cell` на обоих полях строки) и поля настроек
  (`data-saves-on-leave` на их контейнере). В помеченном месте клавиатуру держит
  любой введённый текст, пока он стоит, — даже совпавший с прежним (таблица
  записала бы справочную цену как свою). В форме (быстрый ввод, форма сделки)
  ничего не подтверждается клавишей или уходом: держит всё, что отличается от
  того, с чем поле начиналось, включая товар, выбранный из списка, — пока форма
  не записала и не очистила поля, не закрыта или пока игрок сам не стёр
  введённое. В остальных полях (поиск локации) держит набранный и не выбранный
  запрос. Также держат: поле, помеченное отказом, и раскрытый список настроек.
  Метки закреплены тестом: исчезнет метка в компоненте или её имя в правилах —
  `npm test` падает.
- В форме сделки не своя цена (справочная или своя холодная), которую игрок не
  трогал, не записывается первым подтверждением: оно ставит курсор в цену,
  выделяет её и пишет «Цена справочная — проверь её и подтверди ещё раз»;
  второе подтверждение записывает. Удержанный `Enter` и двойной клик — одно
  подтверждение. Отказы формы идут раньше.

**Масштаб.** Настройка `uiScale`: «Авто» (хранится 0, по умолчанию), 100, 110,
125, 150 %. Масштаб — CSS `zoom` корня окна, один в одном месте; при 100 %
свойства нет вовсе. Окно равно содержимому × масштаб и не больше монитора
(пределы монитора делятся на масштаб). «Авто» выбирает по логической высоте
монитора: от 2160 — 150 %, от 1440 — 125 %, иначе 100 %; монитор известен до
первого показа окна, а после смены монитора окно переставляется тем же
заходом. Значение вне пяти читается как «Авто». Измерение опирается на
стандартный `zoom` (WebView2 / Chromium 128 и новее).

**Локация и рейс.**

- `Enter` или клик по терминалу в поле локации: без рейса — терминал
  становится и просматриваемым, и текущим («Я здесь»); в рейсе — только
  просматриваемым; `Ctrl+Enter` — «Я здесь» всегда.
- «Прилетел» без цели: поле локации спрашивает «Где прилетел?» (акцент,
  подсказка в поле); следующий выбранный терминал становится текущим. Вопрос
  привязан к своему рейсу, живёт в памяти и снимается выбором, сделкой,
  «Взлетел», концом рейса. С целью — как в 14.12.
- Мини-строка: один товар — «MEDS 120 SCU по 2 115, ждём 2 351»; вместо
  отдельного «ждём» — ожидаемая прибыль рейса и доход в час: «≈ +66 720 ·
  337k/ч» (то же число, что в карточке рейса; нет цены у цели хоть для одного
  товара — нет ни прибыли, ни дохода; ожидаемый убыток — красным). Подсказка
  строки несёт «ждём» по каждому товару. Метки «SC» в строке без рейса нет.
- Варианты с неизвестным запасом в точке закупки стоят ниже вариантов с
  известным при любой сортировке; отбор лучших N делается после этого порядка,
  и расстояния запрашиваются сначала для известных. Известный ноль и оценка по
  своему замеру — «известно».
- Рейс с несколькими товарами, у которого все закупки на одном терминале, а
  все продажи на другом, — маршрут: своя строка «смеш.» в «Маршрутах» (ключ —
  пара терминалов и набор товаров), числа по рейсу целиком. Такой рейс — один
  замер времени своей пары. Это заменяет слова «простые рейсы» в 8.6 и 8.7.
- Подсказка про клавиши «Взлетел» / «Прилетел» — один раз за всё время, после
  закрытого рейса с не красным итогом, в развёрнутом окне, 15 секунд, с кнопкой
  «Настроить». Флаг `keysHintShown` пишется после того, как подсказка встала на
  экран; если клавиша уже назначена, флаг пишется молча.
- «Выход» в настройках спрашивает подтверждение только пока идёт рейс и стоит
  отдельной строкой.
- Оба конца маршрута в «Маршрутах», «Истории» и заголовке «Вариантов»
  сокращаются поровну, стрелка видна всегда. Треугольник «цена пошла против
  тебя» — малиновый (`--sc-trend-bad`).

**Установщик.** Версия 1.1.0. Свой шаблон NSIS разрешён (отмена решения
14.15): `src-tauri/installer/installer.nsi` — шаблон `tauri-bundler` 2.10.1
(его использует `@tauri-apps/cli` 2.12.1; тождество доказано совпадением
сгенерированных скриптов) плюс помеченные блоки `; SC TRADE THEME:`.
Нетронутый оригинал лежит рядом. Блоки могут только красить: тест пропускает
в них четыре вида строк и одну заменённую строку оригинала (`BrandingText`),
вызовы — только `UXTHEME::SetWindowTheme` и `dwmapi::DwmSetWindowAttribute`.
Обновился Tauri CLI — тест требует пересобрать шаблон. Тёмными стали все
страницы установки и удаления, полоса хода — акцентом, заголовок окна (Windows
11) — в цветах программы; кнопки остаются системными. Цвета тесты берут из
`src/ui/theme.css`. Рядом лежит `preview.nsi`: те же страницы без единого
действия — для просмотра оформления.

**Известные ограничения версии.** На ширине окна 380 px от концов маршрута
остаётся одна-две буквы (полное имя — в подсказке). В быстром вводе клик по

может свернуться по простою с недописанной строкой. Выпадающие списки и
системные подсказки масштабом окна не увеличиваются. После перезапуска вопрос
«Где прилетел?» не повторяется. Окно установщика никто из исполнителей не
видел: его смотрит пользователь.

### 14.17. Версия 1.1.1: второе слово «торговца» (2026-10-10)

«Торговец» прошёл версию 1.1 второй раз (`.superpowers/test-build/TRADER-REVIEW-2.md`): всё из первого
слова исправлено, а мешают теперь «острые края вокруг клавиатуры». Этот раздел уточняет 14.16; где они
расходятся, верен этот.

**Клавиатура.** Свойства 14.7 и 14.11 не изменены; Rust-часть, слой платформы и модель держателей не
тронуты.

- **Один `Esc`.** Нажатие `Esc`, когда окно держит клавиатуру, всегда заканчивается тем, что клавиатура у
  игры. Компонент сначала делает со своим вводом то, что делал по `Esc` раньше (строка таблицы и поле
  настроек отбрасывают черновик, быстрый ввод очищает поле, поиск сбрасывает запрос, форма сделки
  закрывается), и в том же нажатии клавиатура уходит. Порядок обязателен: возврат назначается на момент
  после обработчика компонента, иначе уход фокуса записал бы черновик, который `Esc` отбрасывает. Новое
  нажатие на поле или на кнопку ввода отменяет назначенный возврат. В 14.16 сказано, что `Esc` в
  настройках сохраняет число, — теперь он его отбрасывает.
- **Запрос в поиске — не ввод.** Единственное исключение из правила 14.16 («автоматический возврат не
  становится причиной потери введённого»): набранный и не выбранный запрос в поле поиска (поле локации,
  поле «Товар» быстрого ввода) клавиатуру не держит и сбрасывается, когда поле теряет курсор. Поле поиска
  помечено (`data-picked`); метка закреплена тем же тестом, что `data-cell` и `data-saves-on-leave`.
  Выбранный товар, набранные цена и количество держат по-прежнему. Причина: случайная клавиша игры в пустом
  «Товаре» держала окно бессрочно.
- **Переключатель «Куп.» / «Прод.» быстрого ввода** — пятая кнопка, открывающая ввод: клик меняет сторону и
  ставит курсор в цену. Пока курсор страницы стоит на переключателе (пришли клавишей `Tab`), сторож
  клавиатуру не отдаёт; правило 15 секунд действует как в пустом поле. Сторона — одно значение для
  переключателя и для записи: товар, которым терминал торгует с одной стороны, встаёт на неё, иначе —
  сторона открытой вкладки (раньше вкладка не учитывалась, и новый для терминала товар на вкладке «Продать»
  записывался как покупка). Выбор товара и запись строки сбрасывают сторону, выбранную вручную.
- **Знак «Клавиатура у игры»** стоит шесть секунд на месте «Esc — в игру» после возврата по таймеру (не после
  `Esc`, не после клика в игру, не после пути «ни одно поле не редактируется»). Клик в поле снимает его.
  Знак показывается по намерению вернуть клавиатуру, до ответа Windows.
- **Не изменено и известно:** клик или `Tab` на обычную кнопку открытой формы отдаёт клавиатуру игре через
  старый путь сторожа, без знака; недописанная строка быстрого ввода после этого может пропасть при
  сворачивании окна. `Esc` при раскрытом системном списке настроек не проверен.

**Таблица, рейс, подсказки.**

- Выбор терминала в режиме «Где прилетел?» показывает его по тому же правилу, что прилёт с целью (одна
  функция): с грузом в трюме — сторона «Продать».
- Подсказка про клавиши не исчезает сама (в 14.16 — 15 секунд): уходит по крестику, по «Настроить», при
  смене другим сообщением и когда игрок сам назначил «Взлетел» или «Прилетел». Сворачивание её не снимает.
- Порядок строк таблицы терминала не меняется, пока курсор в поле таблицы или раскрыта любая строка;
  применяется, когда раскрытых строк нет и курсор ушёл. Каждый клик по заголовку «Товар» или «ROI»
  применяет порядок сразу и берёт его за новый удерживаемый. Площадка нажатия заголовка — не меньше
  28 × 24 px (вниз, в край первой строки: сверху её обрезает прокручиваемая секция).
- Форма «Купил», когда запас в точке закупки неизвестен и количество предложено, ставит «?» и пишет «Запас
  неизвестен: количество — по трюму и бюджету» (тот же признак, что у вариантов).
- Подсказки на экране у слов «Худший», «Время», «скорость выучена», «Мин–макс», у «≈» и «UEC/ч» берутся из
  одного модуля и говорят то же, что раздел «Обозначения» README.
- Поле клавиши после отказа возвращается к сохранённому значению, причина остаётся под полем.
- Когда «Авто» впервые выбирает масштаб больше 100 %, один раз показывается «Окно стало крупнее…» (флаг
  `scaleNoticeShown`).

**Разрешения.** Список разрешений окна закреплён тестом (`tests/release/permissions.test.ts`): нет доступа к
файловой системе, оболочке, диалогам и обновлению; в сеть — один адрес, API UEX. README говорит это словами
(«не читает файлы игры»).

**Не взято из второго слова:** поднять минимальную ширину окна с 380 px; 30 секунд вместо 15; не закрывать
знаком клавиатуры индикатор UEX; дольше держать итог рейса в мини-строке.

### 14.18. Сайт программы (2026-10-10)

Пользователь попросил сайт, с которого игроки скачивают установщик: домен `sc-trade.space`, свой VPS, вид «в
духе» официального сайта игры, «но мы не притворяемся им». Сайт — отдельная часть репозитория (`site/`,
`scripts/site/`, `tests/site/`, `tests/site-server/`); программа от него не зависит, а он берёт из программы
только версию, установщик и картинки режима просмотра.

**Страницы.** Статические, собираются скриптом на Node без зависимостей (`npm run site:build`): русская в
корне, английская в `/en/`, «О данных» на двух языках, 404. Сборка подставляет версию, размер и SHA-256
установщика и падает, если установщика нет или его версия не та. Своё лицо: название, значок и палитра
программы; ничего чужого (логотипы, шрифты, картинки RSI / CIG и сервисов). Оговорка «неофициальный фан-проект»
— на первом экране и в подвале. Каждое утверждение о программе берётся из README. На первом экране место под
фоновый ролик из игры (его готовит `npm run site:video` из файла пользователя); без ролика страница закончена.

**Аналитика** (Google Analytics 4) — только после согласия посетителя; пока идентификатор не задан, в сборке
нет ни баннера, ни доменов Google. Почта отложена пользователем: служба ничего никуда не отправляет.

**Обратная связь.** Форма (текст, до трёх картинок, файл лога, контакт) уходит на `POST /api/feedback`
маленькой службе на Node 18+ (одна зависимость, `busboy`) за Caddy на `127.0.0.1`. Свойства, которые держат
тесты: пределы режутся по ходу чтения; тип файла — по содержимому; ни один путь не строится из запроса; адрес
отправителя не пишется ни на диск, ни в журнал (в ограничителе — только HMAC в памяти, не дольше суток);
сообщения старше 180 дней удаляются; cookie есть только у страницы автора и только под `/admin`. Страница
автора: один пароль (scrypt), сессия в памяти, каждое изменение — POST с токеном, удаление по одному, пачкой и
«всё найденное». Устойчивость: отдельный ограничитель для входа, одна отправка на адрес, минимальная скорость
16 КБ/с, бюджеты 40 МБ в сутки с адреса и 200 МБ в час на всех, честная очередь входа. **Чего служба не
обещает** (написано в `site/DEPLOY.md`, 4.13): упорный поток с многих адресов может на время закрыть форму или
занять вход; прочитать или удалить сообщения им нельзя.

**Сервер.** Ubuntu 24.04 LTS, Caddy, служба как единица systemd с ограничениями, журнал ошибок Caddy хранится 30
дней (logrotate), журнала доступа нет. Настройку делает `site/deploy/setup.sh`, который **запускает сам
пользователь**: пакеты только из репозиториев Ubuntu; пароль автора читается с клавиатуры; порт SSH берётся
только из показаний системы, без них брандмауэр не трогается; включённый брандмауэр скрипт не выключает
никогда; порядок шагов — брандмауэр, служба, Caddy последним; настройки SSH не меняются. Выкладка файлов сайта —
`npm run site:deploy`: только по ключу, ничего не удаляет, без `--yes` — пробный прогон.

**Не проверено ничем, кроме чтения и тестов над текстом:** `setup.sh`, единица systemd, правило logrotate и
Caddyfile ни разу не запускались на настоящем сервере; выкладка шла только пробным прогоном. Первый запуск —
у пользователя, по порядку из `site/DEPLOY.md` (раздел 4.6 — проверка после настройки).

### 14.19. Версия 1.2 (2026-10-13)

Состав — пятнадцать пунктов в четырёх пачках, каждая со своей пробной сборкой: А «Расчёты», Б «То, что мешало
группе» (правка сделок, мини-строка рейса, «Выгоднее»), В «Новое» (справочная по товарам, «цена хуже — куда
лететь», ящики и где корабль может загрузиться, избранные маршруты), Г «Порядок в доме» (политика окна,
издатель, `SECURITY.md`, README и сайт). Здесь записано то, что уже сделано; остальное дописывается по мере
пачек.

**А. Расчёты.**

- **«Продать здесь или лететь дальше» — по добавке.** Время, которое рейс уже занял, потрачено при любом
  выборе, поэтому вариант судится по тому, что он ДОБАВЛЯЕТ к продаже здесь (весь груз × разница цен), и по
  времени пути туда. Порядок: сначала места, где платят больше и время известно, — по добавке в час; потом
  места, где платят больше, а времени нет, — по добавке; в конце те, где платят не больше, чем здесь. Прежний
  расчёт делил прибыль всего рейса на всё его время и с каждой минутой рейса сглаживал разницу между
  вариантами.
- **Время пути — перелёт и выгрузка.** Берётся медиана «перелёт + выгрузка» по своим рейсам пары, у которых
  есть обе отметки; иначе расчёт по расстоянию (со знаком «≈»); иначе времени нет и остаётся одна добавка.
  Медиана целых рейсов сюда не идёт: в ней погрузка, а она уже позади.
- **«Худш.» больше нет.** В подробном виде стоит «По нижней» — добавка по нижней цене диапазона. У своей цены
  диапазона нет, там прочерк. В раскрытом варианте маршрута «Худший» — прочерк, когда обе цены свои.
- **Настройка «Подробные расчёты»**, по умолчанию выключена. Без неё у варианта два числа: добавка и время. С
  ней — ещё «По нижней», «В час» (добавка, делённая на время пути) и обычный темп игрока под таблицей: прибыль
  последних 20 рейсов, потерянные входят, продажи без закупки — нет, делённая на их время. Темпа нет, пока нет
  ни одного законченного рейса.
- **Потерянные рейсы на маршруте** (с той же настройкой): в «Моих маршрутах» у маршрута пишутся удачные рейсы
  из всех попыток, а прибыль и UEC/ч — с потерями. Маршрут потерянного рейса — по его сделкам, если он успел
  что-то продать; иначе от точки закупки к цели, которая стояла, когда груз списали. Без цели рейс не
  относится ни к какому маршруту. Маршрут, который только теряли, в списке не появляется.

- **«Обнулить маршруты»** (просьба пользователя после первой сборки пачки: «маршруты = история», обнулить рейтинг
  можно было только удалив историю). Кнопка под таблицей маршрутов ставит настройку `routesSince` — минуту, с
  которой считаются маршруты, свои времена по парам, число рейсов по паре и обычный темп: в счёт идут рейсы,
  закончившиеся с этой минуты. История и сессии не меняются, ничего не удаляется; «Вернуть прежние» снимает
  настройку. Вопрос перед обнулением — строкой под шапкой, как у «Груз потерян».

**Б. То, что мешало группе** (решение пользователя 13.10: пачки Б и В идут подряд, одна сборка после В).

- **Мини-строка рейса, вариант Б2.** С одним товаром в трюме строка — товар, количество, цена покупки, стрелка и
  сторона продажи в точке цели. Своя не холодная цена стоит в рамке с подписью «моя» и возрастом и не
  двигается; за ней в одном месте по три секунды сменяются «мин» и «макс» — границы диапазона UEX для цели, те
  же числа, что в столбце «Мин–макс» её таблицы. Настройка «Сменять мин и макс в мини-строке» (включена);
  выключена или система просит меньше движения — границы стоят рядом. Нет диапазона — одно число; о цели
  ничего не известно — строка кончается ценой покупки. Слов «по» и «ждём» в этой строке больше нет; несколько
  товаров пишутся как раньше. В 2.0 в ту же рамку встанет ник участника флота.
- **«К цели»: товары своей пары и набор на трюм** (просьба пользователя 13.10: «я на станции А, ребята на
  станции Б — подобрать товары»). Кнопка «цель» в заголовке таблицы показанного терминала делает его целью,
  включает режим и открывает варианты станции игрока. В «Вариантах» переключатель «Куда угодно | К цели» (виден,
  пока цель задана и это другой терминал). Список — все товары, которые станция продаёт, а цель покупает
  дороже, без отбора лучших N и без фильтра по системе: оба конца выбрал сам игрок. Набор: товары берутся по
  очереди, каждый — сколько позволяют место, запас и деньги; сначала товары с известным запасом. Пробуются два
  порядка — больше с одного SCU и больше с одного UEC — и берётся тот, что приносит больше (второй нужен, когда
  кончаются деньги, а не место). Это хороший набор, а не доказанно лучший. Считается из уже загруженных цен и
  запасов, к UEX не обращается.

- **«Выгоднее» вместо «и рядом».** Кандидаты закупки — терминалы той же планеты, как раньше, но рейс с закупкой
  на другом терминале показывается, только если он рядом и лучше. Рядом: пустой перелёт до закупки не дольше
  настройки «Закупка рядом» (10 минут по умолчанию); расстояние, которого UEX не знает, — не рядом; пока
  расстояние не получено, рейс остаётся кандидатом (чтобы его запросили), но в списке его нет. Лучше: ROI
  выше, чем у того же товара, купленного на станции игрока, а если товар там не продаётся — выше лучшего ROI
  отсюда. Свои варианты занимают «Число вариантов», рейсы с закупкой рядом идут после них под строкой
  «Выгоднее: закупка рядом», не больше трёх. В строке — точка закупки, время пустого перелёта и точка продажи.
- **Цель в два шага.** «Цель» у такого рейса ставит целью точку закупки и запоминает точку продажи
  (`targetThenId`); после покупки на точке закупки цель переходит на точку продажи, окно сообщает об этом.
  Отдельной кнопки отмены нет: цель меняется и снимается как обычно. Заголовок списка словами «и рядом» больше
  не кончается (слово автора, 14.10.2026): о рейсах с закупкой рядом говорит строка «Выгоднее: закупка рядом»
  в самом списке.

- **Правка сделки и удаление одного рейса** (группа в тесте ввела не ту цену покупки, списала груз, чтобы ввести
  заново, и сессия ушла в минус). У покупки и продажи можно исправить количество и цену — в идущем рейсе
  (кнопка «Исправить сделку» под карточкой рейса) и в любом прошлом («История», клик по строке). Трюм, деньги
  рейса, маршруты и сессии считаются из событий рейса и меняются сами. Запись в дневнике, которую оставила
  сделка, находится по времени, терминалу, товару, стороне и прежней цене и исправляется: цена — на новую,
  количество после сделки — на разницу (остаток у продавца уменьшается, если куплено больше; склад покупателя
  растёт, если продано больше; не ниже нуля; незаписанное количество остаётся незаписанным). Отказ без записи:
  число не больше нуля; продано больше, чем куплено; покупка идущего рейса не помещается в трюм. Идущий рейс,
  трюм которого правка опустошила, закрывается временем последней продажи. Один завершённый или потерянный
  рейс удаляется из истории двумя удалениями (события, потом рейс), дневник не трогается; идущий рейс удалить
  нельзя.

**В. Новое.**

- **Справочная по товарам.** Отдельный экран в том же окне, как «Настройки» (боковая панель потребовала бы
  менять ширину окна и его привязку к углу). Открывается кнопкой в шапке и кнопкой «места» в раскрытой строке
  таблицы терминала. Товар выбирается поиском; стороны «Купить» (дешёвые сверху) и «Продать» (дорогие сверху);
  до десяти мест: название и где оно, цена с отметкой источника и свежести, запас (при покупке) или склад
  покупателя (при продаже). Фильтры «моя система» и «есть запас» (только при покупке) запоминаются. Клик по
  месту открывает его таблицу; «цель» ставит цель рейса и запоминает прежнюю, чтобы её можно было вернуть.
  Считается из загруженных цен. **Не сделано:** назначаемая клавиша для справочной — это правка перехватчика
  клавиатуры на стороне Rust, её лучше делать отдельно, с `cargo test`.
- **«Цена на месте хуже — куда лететь».** Срабатывает при вводе цены продажи товара, который есть в трюме: цена
  ниже ожидавшейся здесь (оценка до записи новой цены) на порог из настроек (15 %, 0 — выключено) или больше
  и есть место, где груз купят дороже (первое из «лететь дальше» с положительной добавкой). Тогда строка
  в мини-строке и уведомление с кнопкой «Куда ещё?», которая открывает справочную на этом товаре; там при
  грузе на борту и своей цене на месте есть столбец «Добавка». Условие «ниже минимума диапазона» не
  используется: оно срабатывало бы на нескольких процентах.

- **Ящики и погрузка.** Из UEX берутся новые поля: у терминала `has_docking_port` и `max_container_size`, у
  корабля `container_sizes`, `is_loading_dock`, `is_docking`, `pad_type`. Строка «Ящики: любые» — самый большой
  ящик терминала не больше самого большого у корабля; иначе «Ящики: до N SCU», N — самый большой у корабля.

- **Исправленная сделка идущего рейса не доходила до экрана.** Состояние сравнивало рейс с прочитанным из базы только по

- **Исправление сделки и статус рейса.** Продажу без покупки (14.10) исправить было нельзя: проверка «продано не больше,
  чем куплено» отказывала всегда; для такого рейса она не делается. Завершённый рейс, в котором после правки остался
  груз, становится идущим снова (`reopenRun`); если идёт другой рейс — отказ `run_active`. Потерянный рейс статус не
  меняет. «Не помещается в трюм» спрашивается только у покупки, которую увеличили, и по вместимости, записанной в рейсе,
  а не по настройке. Порядок записи: открыть рейс → исправить дневник (он ищется по старой цене события) → исправить
  событие → закрыть рейс; оборванная запись на любом шаге чинится повтором или починкой следующего вызова.
- **«К цели» принадлежит цели.** Включённый режим оставался навсегда и всплывал у другой цели. Теперь его включают
  только «Маршрут» (две точки), «цель» в заголовке терминала и сам переключатель; любая другая установка цели, её
  снятие и конец рейса возвращают «Куда угодно». «Лучшее» всегда показывает «куда угодно». У цели в два шага
  переключателя нет: цель там — место закупки, и пара «отсюда → цель» не та, по которой летят.
- **Цель в два шага.** Конец рейса снимает и второй шаг. Списанный рейс записывает целью место продажи, а не закупки.

  продажу в месте закупки, пока покупка там не сдвинет цель.
- **Быстрый ввод.** Строка принадлежит терминалу: при смене терминала в таблице выбранный товар, цена и количество
  сбрасываются. Запись ещё раз проверяет сторону (`mayWrite`): товар, который терминал на этой стороне не торгует, не
  пишется («Этот товар здесь так не торгуется»). Товар, не торгуемый ни на одной стороне, сторону больше не меняет.
- **Сообщения по таймеру.** Сигнал любимого маршрута и «цена хуже» держатся в мини-строке обычные три секунды, пока идёт
  рейс: под сообщением не рисуются кнопки отметок. Сигнал любимого маршрута не вытесняет уведомление с кнопкой и ошибку:
  ждёт следующей проверки (15 секунд). Звук не копится, пока вывод звука придержан: опоздавший больше чем на две секунды
  сигнал не играется.
- **«Лететь дальше».** Место, которое добавляет больше всех, всегда входит в три показанных (последним, если по ставке в
  час его обошли трое других): далёкое место или место без известного пути может платить намного больше.
- **Мелочи.** Правка, закрывшая рейс, называет его итог; правка, открывшая рейс, говорит об этом. «Вернуть цель» в
  справочной не переживает сворачивание окна. «цель» в заголовке терминала без известной локации говорит, чего не
  хватает. «Закупка рядом» не больше «накладных на пустой перелёт» — под полем строка, что «выгоднее» ничего не найдёт.
  Сводка «Моих маршрутов» называет маршрут с лучшей ставкой из показанных чисел (с потерями, если они включены).

делает цель в два шага простой целью (обе точки введены руками).
